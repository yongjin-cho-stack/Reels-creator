# Reels-creator

원본 광고 영상의 특정 구간(디졸브 없는 컷)을 AI로 리메이크하는 걸 사람이 수동으로 한 번 해보고,
그 과정을 자동화된 에이전트로 굳히는 프로젝트.

**이번 1차 목표**: 똑같이 만들어보는 것. 컷별 이미지는 이미 잘라서 받는 것으로 가정하고,
그 이미지를 영상화 + 조립해서 완성본을 만든다.

## 역할 분담

| | 담당 | 하는 일 | 산출물 |
|---|---|---|---|
| **기획** | 1명 | 컷 정의(`cuts.json`), 캐릭터/장면 일관성 기준(`keycut.json`), 컷별 영상 프롬프트 설계, BGM 방향 | `cuts.json`, `keycut.json`, `refs/` |
| **제작A (영상화)** | 1명 | 받은 이미지 → Kling으로 영상 생성(컷당 3개), 재시도/비용 로깅, `status` 갱신 | `videos/`, `cost.log` |
| **제작B (편집)** | 1명 | 애니매틱 제작, 확정된 영상 조각 조립, BGM 입혀서 최종 렌더 | `animatic.mp4`, `final.mp4` |

**진행 순서**: 기획이 컷 1개라도 먼저 정의해서 넘기면 → 제작A가 바로 영상화 시작 → 제작B는 BGM만 먼저 준비해두다가 영상 나오는 대로 조립.

## 폴더 구조

```
schemas/          cuts.json / keycut.json 예시(틀) — 실제 작업 파일은 루트에 생성
refs/             컷별 대표 프레임 / 구도 레퍼런스 이미지
keycuts/          캐릭터 기준 이미지 (얼굴·의상·소품 확정본)
videos/           컷별 생성된 영상 (컷당 여러 개, 그중 베스트 선택)
```

## 파일 형식

### `cuts.json` — 기획이 채움, 제작A·B가 읽음

| 필드 | 뜻 | 채우는 사람 |
|---|---|---|
| `id` | 컷 번호 (1부터 순서대로) | 기획 |
| `start_s` / `end_s` | 이 컷의 시작/끝 시각 (초) | 기획 |
| `shot_type` | 샷 종류 (클로즈업/미디엄샷/와이드샷 등) | 기획 |
| `characters` | 이 컷에 나오는 인물 이름(들) | 기획 |
| `action` | 이 컷에서 인물이 뭘 하는지 (한 문장) | 기획 |
| `camera_move` | 카메라 움직임 (고정/줌인/줌아웃/패닝 등) | 기획 |
| `keycut_id` | 이 컷에 쓸 캐릭터 기준을 `keycut.json`의 어느 카드에서 가져올지 | 기획 |
| `ref_frame` | 이 컷에 쓸 이미지 경로 (기획이 잘라받은 이미지, 제작A가 이걸로 영상화) | 기획 |
| `status` | 진행 상태 (`대기` → `영상생성중` → `베스트컷선택` → `완료`) | 제작A가 갱신 |

### `keycut.json` — 기획이 초안, 사람이 승인

| 필드 | 뜻 | 비고 |
|---|---|---|
| `id` | 키컷 카드 ID (`cuts.json`의 `keycut_id`가 이걸 가리킴) | 캐릭터/장면 세트당 하나 |
| `character` | 인물 이름 | |
| `face` / `outfit` / `props` | 얼굴·의상·소품 묘사 — **한번 정해지면 이후 모든 컷에서 안 바뀌어야 함** | 승인 게이트 기준 |
| `time_of_day` | 시간대/장소 분위기 | |
| `approved` | 사람이 승인했는지 (`true`/`false`) | 승인 전엔 다음 단계 진행 안 함 |
| `approved_image` | 승인된 키컷 이미지 경로 (승인 전엔 `null`) | |

## 승인 게이트 (사람이 확인해야 넘어가는 지점)

1. **키컷 승인** — 캐릭터 얼굴·의상·소품이 확정되는 시점
2. **베스트컷 선택** — 컷당 생성된 영상 여러 개 중 원본과 제일 비슷한 것 선택

## 이미지/영상 생성 API

- **영상**: Kling 2.5 Turbo Pro (fal.ai 경유)
- 이미지는 기획 쪽에서 이미 잘라서 제공하므로 이번 1차에서는 별도 이미지 생성 불필요
